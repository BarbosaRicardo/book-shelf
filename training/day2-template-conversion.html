07:00locks · cross-check · Save As

Rule zero: rename it before you touch it

Do this first, every timeSave As, rename, then modify. Every device change, data type change and mapping change after this point is destructive — and the project you started from is very likely running a plant right now.
  • A project that was not closed properly stays locked. Right-click to unlock — but only the user or credential that created the lock can release it.
  • Admin credentials cannot unlock a project locked under another engineering credential. Find the person, not a workaround.
  • Cross-check and clear the existing errors before you change anything. Otherwise you cannot tell your new breakage from the breakage you inherited.

The right template is the one you change least

Score four candidates against a new project. The point is not the arithmetic — it is that this decision is made once, on evidence, instead of by whoever remembers a project name.

Build this onceA shared Excel inventory: project name, inverter brand and type, met station, FPS, substation connection, and any other device worth reusing. Filter it to find the closest template instead of guessing.
  • A project with the same inverter type beats one with a completely different inverter, even if other things match.
  • A hybrid project is the better base for another hybrid project — battery and storage configuration is expensive to add and cheap to inherit.
  • Reuse the project with the largest matching device set. Meter-only changes are easy; control-architecture changes are not.

07:12globals · data types

One data type, a hundred broken references

  • Update the inverter and feeder counts in global variables first. The worked example ran 15 inverters across 3 feeders.
  • Change the inverter-specific data type and its naming consistently — the example moved from SunGrow 4400 to SunGrow 3150U.
  • Strings such as PT01 and PT02 are not themselves mapped, but keeping the naming consistent is what makes the project traceable six months later.
Why it cascadesChanging a data type or a reference breaks the mappings between programs, substations and data points. Every one of those surfaces as a cross-reference error — which is the good news, because it means the tool will hand you the list.

  • Change one inverter or reference at a time. Batch the changes and you lose the ability to tell which one caused what.
  • Ctrl+H finds and replaces references — SG 4400 to SGT 3150. Use Replace All only when you understand the scope; otherwise you have traded a known list of errors for an unknown one.
  • Delete references to things that do not exist on the target inverter, then run the cycle again.
  • Ctrl+Z and the undo arrow will revert — but save first, because undo can reach into other program changes you meant to keep.
Small change, real errorA changed register or name creates errors in places you did not edit — a prior reference to 10 that now has to be 09. The cross-check finds it; guesswork does not.
07:25point lists

The vendor point list is the contract

  • Match register numbers and data-point names to the target inverter's point list. That document, not the old project, is the authority.
  • Register numbers may not be mapped directly — but the naming convention normally mirrors the register number, which is what makes a mismatch visible.
  • Copy and paste accelerates repeated mappings. On a first conversion, do it manually and one at a time anyway; you are still learning where this particular vendor differs.
Carried from Day 1Everything about signed vs unsigned, 16-bit vs 32-bit, and word order applies here unchanged. A point list that reads correctly in the vendor document still decodes to nonsense if the map disagrees about the byte order.

07:57programs · status · control

What you touch, and what you leave alone

Most of a plant project does not change between sites. Knowing which half is which is the difference between a two-day conversion and a two-week one.

Sort each one

Fault, comms-loss, remote-enable, clamp, PPC-control and inverter-status signals

Every one of these has to be mapped per inverter. Adding an inverter means adding all of them.

Generic group control and NOC calculations

Fixed program logic. Leave it alone.

Met station calculations and PF / performance calculations

Unchanged between projects — the inputs change, the arithmetic does not.

Redundancy logic that blocks commands when the RTU is not primary

Generally unchanged — except that the new inverter's references have to be added to it. The logic stays; its coverage grows.

Module counts and model-specific control logic

Inverter-specific by definition. And if the control type is fundamentally different, expect to write a new control implementation rather than adapt this one.

Ignition mappings for the added inverter

Control and feedback points both. Follow the cross-reference errors into the programs and function blocks to find every place they are needed.

08:07LGI · tuning · metering

The settings that are project-specific

  • LGI and tuning settings vary per project: plant rating, Q rating, evolution period, Q high and low limits, jetband changes, P-limit delay.
  • Declare them at project level and pass them to Grid Connect automatically — settings scattered across blocks are the ones that get missed on the next conversion.
  • Manual tuning is still needed when the modelled behaviour and the real plant disagree. The model is a starting point, not an answer.
  • Add the required POI meter points and map them on both the read side and the project side. Add met station data when the site has one.
  • Update QSC data points or indexes when names, data types or indexes differ — then follow the resulting errors to the affected address or name.

08:17brand-new inverter models

When nothing in the inventory matches

What a brand-new inverter needs

  • Its Modbus connection and its point list
  • An inverter structure — the data type that holds its variables
  • Read and write blocks
  • Grid Connect mappings and the required status and control points
The shape never changesHowever exotic the inverter, the same two-block interface holds: inverter data flows into the MPC / Grid Connect block, and Grid Connect setpoints and commands flow back out to the inverter. Everything else is translation.
  • Model-specific signals — fault status, module count, naming — get converted into the common Grid Connect representation. That conversion is the work.
  • Experience with existing SunGrow, SMA or other implementations is how you spot the equivalent point across models when the vendor names them differently.
08:24custom types · global vs local

Why the custom data type exists

A data type is not bookkeeping. It is the thing that lets four vendors' inverters present one face to the control logic.

Normalising a faultToggle any vendor bit
Grid Connect sees
Fault = FALSE

Grid Connect wants one true/false fault input. The data type is where four model-specific bits become that one bit — so the control logic never learns which vendor it is talking to.

  • Custom data types define reusable structures holding inverter variables — on/off status, control mode, faults, setpoints.
  • They let you pass an entire structure into a function block instead of declaring every variable by hand, which is where the object-oriented value is.
  • Global variables read and write across programs and function blocks; local variables stay in their defining scope unless exposed as inputs or outputs.
  • The project uses global structures to connect the inverter side to the Grid Connect side.
  • Global retained variables carry memory-related risk — understand it before extending the pattern.
  • The compiled repository exposes structures, function blocks, data types and programs for inspection and reuse. Read it before you write something that already exists.
Day 3 qualifies thisMixed vendors on one site — SunGrow and SMA together — need parameters assigned at the variable level rather than embedded uniformly in a shared data type. Same idea, one level of indirection more.

This is the trap: a number that looks reasonable is not the same as a number the declared array actually accepts. Validate the bounds the code declares.
