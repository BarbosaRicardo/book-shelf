07:10RTAC redundancy · metering

Only one RTAC gets to command

  • A heartbeat identifies the primary RTAC. A non-primary RTAC asserts disable control, so no inverter commands leave the secondary.
  • Keep both RTAC connections initialised. Breaking the secondary's connection makes the transition worse, not safer.
  • POI meter points must be assigned and mapped in the POI area. Line-to-line and phase-line voltage may need conversion — check which one the meter is actually serving.
  • Mirroring blocks handle primary/secondary selection, scaling, and ceiling/floor limiting for the redundant signals.
Carried from Day 2The redundancy logic that blocks commands when an RTU is not primary is the same block you inherited from the template — generally unchanged between projects, except that every new inverter's references have to be added to it.
ConsequenceStatus feedback is taken from the primary RTAC, not the secondary. A status page fed from the wrong one is a page that quietly disagrees with the plant.
07:13project parameters · retained variables

The parameters that vary by project

  • Full-scan initialisation, project-level parameters, retained variables, SCADA inputs and substation/QSC points all have to be assigned consistently across the project.
  • Setpoint feedback is reused by bumpless transfer for P, Q and V whenever the active source changes — that reuse is what makes a source change a smooth move instead of a step.
  • Inverter ratings, ramp limits, minimum PV setpoints, P/Q errors and scaling values vary by project. These are the numbers Day 2 said to declare at project level and pass to Grid Connect.

07:18inverter parameters · visibility

You cannot see what each inverter was told

The visibility gapThe MPC block assigns setpoints directly to each inverter, and that assignment is not visible in the main program. To see what a given inverter was actually commanded, expose it — through DDR, or through dedicated global variables.
  • Inverter parameters cover P and Q ratings, error corrections, minimum PV setpoints, feedbacks, status and on/off conditions.
  • IBR read logic can be a program rather than a function block when it only initialises or reads data and has no meaningful inputs and outputs. A function block with nothing to pass is ceremony.
Qualifies Day 2Day 2 made the case for putting inverter variables in a shared custom data type. Here is the limit of that: mixed vendors on one site — SunGrow and SMA together — need parameters assigned at the variable level, not embedded uniformly in one shared type.

Both things are true. The data type still normalises the signals; what cannot be shared is the per-model parameter values behind them.

07:23quality · source selection · plant setpoint

What happens when the meter goes bad

  • POI meter quality is checked from primary to secondary. Bad quality can trigger a ramp-down, or continued operation at the last valid setpoint — whichever the control-network definition specifies for that site. This is a project decision, not a default.
  • Active sources may be SCADA, QSC or another project input. Only the active source supplies the standard setpoint — the others are ignored until they become active, and then bumpless transfer smooths the handover.
  • The intermediate setpoint takes the standard setpoint plus arithmetic and PFR compensation, and becomes the final MPC plant setpoint.
  • Final P setpoints are constrained by LGI limits — a 50 MW limit means no output above 50 MW, whatever the source asked for.
  • The final plant setpoint is the target that ramp logic, PID control and the individual inverters all chase.
Sequencesource → bumpless transfer → + arithmetic, + PFR → intermediate setpoint → LGI clamp → final plant setpoint → ramp → PID → inverters
Ask on every projectWhat does this site do on bad POI quality — ramp down, or hold the last valid value? If nobody can answer from the control-network definition, that is the finding.
07:28timing · the number that decides everything

The timing budget

Two ratios from the session, and they cascade all the way back to which protocol you chose on Day 1.

Ramp → required rates
POI meter — at least 10× faster
100 ms
PID — at least 3–4×, 5× preferred
200 ms

Can your protocol feed it?

  • POI meter data should be at least 10× faster than the ramp. For a 1-second ramp, that means meter data arriving at roughly 100 ms.
  • PID execution should be at least 3–4× faster than the ramp, with 5× described as preferable.
  • Later in the session, the same rule stated from the other end: the plant regulation execution period must match the POI meter response. A 100 ms execution period needs 100 ms data behind it.
Outside the room · the standard behind the numbersIEEE 2800-2022 sets performance targets that these ratios exist to meet. For primary frequency response: reaction time minimum 200 ms, default 500 ms, maximum 1 s; rise time 2 s minimum, 4 s default; settling time 10 s default; damping ratio 0.3 default; settling band 2.5% of change by default. For automatic voltage regulation: reaction under 200 ms, step response between 1 and 30 s as defined by the transmission operator, damping ratio above 0.3.Nor-Cal Controls, summarising IEEE Std 2800-2022, Sep 2024

  • PFR calculates a real-power compensation from the POI frequency deviation and applies the resulting delta to the MPC P setpoint. It does not replace the setpoint; it adjusts it.
  • Reactive-power control applies voltage compensation and power-factor limits — the example range given was 0.95 to 1.05.
  • Q output is either constrained by those power-factor limits, or provided directly within the configured maximum and minimum Q limits. Which one applies is a configuration choice, and worth knowing before you tune anything.

07:33inverter inclusion · feeder control

Taking an inverter out of the maths

  • HMI and SCADA commands can add or remove individual inverters or whole feeder groups from the MPC calculations — for lockout, maintenance, or any other operating condition.
  • Feeder-level and individual-inverter include controls are separate. Cross-references will trace the source logic behind each signal.
  • A remote-enable signal going false excludes that inverter from the MPC calculations.
  • Reusable loop logic must reset its calculation inputs to zero where required — otherwise repeated inverter calculations accumulate values nobody intended.
The whole plant, disabled by a 2A value of 2 arriving from an RTAC during initialisation — or after retained variables are wiped — can disable remote enable for every inverter. The fix is not a restart: trace the HMI or RTAC command and restore it. This is a plant-wide outage caused by a single unexpected enumeration.

Why the library mattersGrid Connect's PI accumulates the previous P-term with the new error × KP term, so the output can reach 100% even when KI is zero. The SCLutils.PID library used in the existing trim-mapping logic cannot do that — with KI at zero it never gets there. Same tuning numbers, different outcome, depending on which block you are in.
  • Start KP around 0.3–0.4. KP is the booster; KI provides the compensation and the smoother response.
  • The test configuration was KP 0.4, KI 0.01 — and excessive KP was identified as the more significant problem, not KI.
Deadband, accounting for clamping

DVDQDVDQ is the relationship between a voltage change and the Q response. Set it too aggressively and a small voltage deviation commands maximum Q. Voltage control ramps toward a voltage setpoint normally — but bypasses the ramp during a Volt-VAR event to deliver direct Q compensation.
08:02operating parameters · online values

Looking at it while it runs

  • The plant regulation execution period must match the POI meter response. A 100 ms execution period requires meter data at that rate — the same budget as slide 8, stated from the controller's side.
  • PI reset clears accumulated controller parameters after a setpoint-source change or an event such as DFR or PFR. Without it, the integrator carries history that no longer applies.
  • IEEE 2800-related behaviour has a separate bit where the project requires it.
  • Online Grid Connect parameters are exposed through the plus button beside the MPC block. Values can be overridden or forced for testing, and revert on reboot unless retained.
  • Night-time Q response may be supported through a plant-loop condition and a separate operating mode. implementation not confirmed
  • Battery-related logic exists in the library but was outside the scope of this project.
Connects to Day 1Forcing a value requires the full project download, not a logic-only send. If you plan to override online parameters during commissioning, that decision was made back on Day 1's send screen.
08:11Dynamic Disturbance Record

Proving the plant actually responded

DDR records high-speed signals to CSV — the evidence behind a P-COD test, and the only practical way to see what each inverter was really commanded.

DDR configuration · 0 channels
  • DDR compares P/Q behaviour, PFR response and setpoint transitions during P-COD testing. It can validate a requirement such as reaching 100% response within 5 minutes of a 0-to-100 setpoint change.
  • Recording is event-driven or periodic, with configurable sampling period, UTC or local time, output path, file name, folder size and file size.
  • The path creates a project-side directory — it does not point at a folder on your laptop. This surprises people once each.
  • Data points need fully qualified references — program.PRG.main.counter — plus a channel assignment and units where they apply.
  • The CSV opens straight into plotting and analysis. DDR is for testing across projects, not only Grid Connect ones.
Carried from Day 1DDR needs both its library and its extension installed. Half of it is the usual reason it is not there when you go looking.
08:22Grid Connect extension · reusable maps

The version of this that is less work

  • The Grid Connect extension assigns parameters directly, with less programming than the current function-block approach.
  • Reusable maps support multiple clients and inverter vendors — a map for SMA, a map for SunGrow. Holding registers and other Modbus points are defined once in a map and reused across devices.
  • Adding another client or inverter becomes selecting the right existing map instead of updating mappings in several program locations. That is the whole of Day 2's conversion work, collapsed.
  • Projects and extension configurations can be exported and imported into other projects.
  • Compatibility with newer Grid Connect versions was considered likely. not confirmed
Where the three days pointDay 2 taught the manual conversion because that is what these projects are today. This slide is the argument for not needing it — the same mapping, declared once and selected per device.

Knowledge checkseven questions

Seven from the control chain

01The plant ramp is 1 second. How fast must POI meter data arrive?

And the PID needs at least 3–4× the ramp rate, 5× preferred. Both ratios come off the ramp time.

02KI is set to zero. Which block can still drive the output to 100%?

SCLutils.PID, used in the existing trim-mapping logic, cannot reach 100% response with KI at zero. Grid Connect's accumulation behaviour can.

03Operating at 56 MW with 5% clamping. Roughly what deadband?

Deadband has to account for clamping. 56 MW × 5% = 2.8 MW of clamping band; the derived deadband was around 280 kW, so ~300 kW was suggested.

04Every inverter has lost remote enable after a restart. Most likely cause?

Trace and restore the HMI or RTAC command. A restart on its own does not fix it — it is what caused it.

05Why is a 30-second clamp delay worse than 15?

A clamped setpoint continues ramping upward. The longer you wait to recognise the clamp, the larger the setpoint/output gap that has to be closed at once.

06You need to see what setpoint inverter 3 was actually sent. Where do you look?

The MPC block assigns setpoints directly to each inverter and the assignment is not visible in the main program. You have to expose it deliberately.

07You set the DDR output path to a folder on your laptop. What happens?

The path creates a directory on the project side. Retrieve the CSV from there.
