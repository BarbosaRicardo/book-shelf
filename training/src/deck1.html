07:05WebPatrol · licensing · network

Getting in, and proving the path exists

Before any protocol argument is worth having, confirm you can reach the box and that the port you need is actually open.

  • Reach the SCL WebPatrol interface at https:// + the RTAC IP. First login sets a password; after that it is username and password.
  • Device Management is where license files go — uploaded through the firmware upload workflow even though a licence is not firmware. It appears under License Features after roughly 3 minutes.
  • Check IP settings, and configure IP bonding where the site needs it.
  • Licences for Grid Connect, DDR and the rest are requested from SEL and arrive as a file you upload the same way.
  • Security tools will ping a device and check its ports. A port that does not show as open is usually a firewall, not a device fault — that is a network-team ticket.
  • For packet capture, use Connected IEDs to isolate one device. The Utilities capture pulls traffic from everywhere and buries the thing you are looking for.

07:12backup · cross-check · send

The firmware update that erases your plant

The one that bitesA firmware update can wipe the active project and leave the RTAC looking like a brand-new device with nothing on it. Download the project locally first, then upload it through Project Management and activate it after the update.
  • Cross-check before you send. A clean save is not a clean project — errors surface at the bottom of the interface only once cross-check runs.
  • Send downloads to the RTAC after you supply the port and credentials.
  • Reinitialising retained variables writes zeroes and rewrites the retained values.
  • Advanced send settings let you exclude selected areas — Ethernet settings, reader settings — from the download.
  • Avoid a V0 firmware release. R155 V0 is the first build of the R155 series and carries the most bugs; take V1 or later where one exists.
Symptom → causeRepeated "reconnecting" messages followed by the project failing, while cross-check reports zero errors and zero warnings, points at a watchdog or a reference problem — not at the network.

07:42Manage Library · extensions · devices

Compiled library, or project item?

The distinction decides where the thing lands, how you version it, and whether it can be edited at all.

Sort each one

A compiled SCL library arrives as a packaged version — 0.17, say.

Installed through Manage Library. When a reference will not resolve, hover it — the tooltip names the version you actually need.

Uncompiled source content someone handed you.

Uncompiled content comes in as a project item, not an installed library.

DDR — the Dynamic Disturbance Record you will use on Day 3.

DDR needs both its library and its extension. Half of it installed is the usual reason it is not there when you go looking.

  • GridConnect normally ships inside the SCL project. To take a newer SCL-provided version — 3.5.9.2 replacing 3.5.9.0 — remove the existing project reference first, then insert the new one.
  • Extra SEL devices, DNP3 devices, IEC 61850 devices and OPC UA components are inserted through the project tree. For the less familiar protocols the device manual is still the authority.
  • Custom libraries must use RTAC-supported data types. An SCL type such as a measured value may need the corresponding RTAC library type instead.

07:53DNP3 client & server

Four numbers have to agree

IP address, port, DNP server address, DNP client / master address. Get one wrong and the traffic looks fine while the device stays offline.

Why is my DNP3 device offline?

  • For a client, the server IP and server port must match the remote server — a server listening on 20001 means you put 20001 here. The client address is commonly zero unless the system demands otherwise.
  • Coming from Ignition? What Ignition calls the destination address is the DNP server address here. In T1S you only specify the server when acting as a client; the RTAC makes you set both sides, and will not negotiate them for you.
  • Reverse the client and server DNP addresses and you get the worst failure mode there is: IP traffic acknowledged, application layer dead, device offline.
  • The client IP port identifies the local source of the connection. Multiple DNP3 clients get different ports — RTAC Architect can increment them for you. Use netstat -an or a capture to see what is already taken.
  • A server can allow anonymous connections, but the DNP addresses still have to line up. Wireshark's application-layer view will show you the addresses actually on the wire.
  • DST and UTC offset can be handled globally; with the global setting off, configure them per device.
  • The server decides which class a value goes out on — you only choose how often to ask. As a client you cannot pick what lands in class 1, 2 or 3.
  • Integrity poll at 0 disables it; a few minutes is common, to stop every value arriving all the time and flooding the link.
  • Class 1 / 2 / 3 at 100 ms is as aggressive as it goes; 500 ms to a minute is what people actually run. The pattern under bandwidth constraint: leave the class poll slow — five seconds, say — and add a custom request for just the analog values you need at 500 ms.
  • Poll timeout is a diagnostic. Set it to 500 ms against a device that answers once a second and the failure count climbs steadily — that climb is the setting, not the device.
  • A larger event buffer preserves events across a connection loss — rarely changed from the default.
The bits the device gives you backOffline true means no connection. Send, receive, failure and success counts tell you whether messages are passing and where they stop. And control disable: when this RTAC is not primary it goes true, which is how commands are held back on the secondary — so if it is true while you are primary, the fault is in the code, not the link. Day 2 wires it into the redundancy logic; Day 3 shows the heartbeat that drives it.
These bits are usable in logicDevice tags can be read straight from structured text at attribute level — if offline then assign bad quality, and so on. You do not need a separate mapping to act on a device's own status.
Speaker noteThe reversed-address case is worth dwelling on. Everyone's instinct on "device offline" is to blame the network, and the network is provably fine — that is what makes it expensive.
08:10DNP3 data types

Right object, wrong variation

The device comes online and the values are still wrong: integers where you wanted floats, no timestamps, no flags, or events that never arrive.

Variation picker
Dead bandDead band decides when instantaneous magnitude gets copied to magnitude. A zero dead band of 0 disables the zero threshold; set it to 2 and anything below 2 reads as zero. Set the dead band too wide and magnitude simply stops updating — a dead band of 100 against a raw range of 0–100 means magnitude never changes at all.
Do not type these by handThe point list grid is Excel-ready. Copy the whole thing out, build the names and numbers with ordinary spreadsheet formulas, and paste it back. Clicking and backspacing through a few hundred points is how the mistakes get in.
  • In existing PVC projects the instantaneous magnitude is often preferred, precisely so a badly configured dead band cannot hide the value.
  • Use measured-value types for floating point and integer types for integers — mixing them is how you get an integer where a float belonged.
  • Double-bit inputs carry four states across two bits: 00 no value, 01 on, 10 off, 11 invalid. IEC 60870-5-104 keeps 00 and 11 but reverses on and off. Read a 104 device as if it were DNP3 and every status is inverted.
  • SPC controls cover pulse, latch-on, latch-off and related attributes. A latch command can appear as a pulse on the server side.
  • Feedback status can let command status stand in for a separate binary input.
  • Counters use object 20; frozen counters use 21.
08:29serving data out

Serving it back out

  • Server setup needs the server IP, DNP addresses that match the far side, and a configured DNP server map.
  • Point numbers must match between client and server. Static and event-driven data use different object types and variations, and the event class and variation settings decide how a value is actually transmitted.
  • Client or server is not a label — it determines whether the device writes to register and point data or serves it.
  • The instruction manual shipped inside the software documents the standard data types, protocols and configuration concepts. It is the first place to look, not the last.

08:39Modbus register mapping

Two registers, one number

Modbus drops the DNP addresses but adds its own arithmetic: a 32-bit value eats two 16-bit registers, and both sides have to agree on which half comes first.

Register layout · 0 points

  • Port 502 is the default. Two anonymous Modbus servers cannot share a port — give them explicit IP addresses or separate ports.
  • Maps cover coils, discrete inputs, holding registers and input registers; coils and holding registers do most of the work.
  • A shared mapping address can be reused across several RTU server devices.
  • Match signed against unsigned, integer against float, 16-bit against 32-bit, and MSB / LSB ordering — on both sides.
  • MBBC exposes the individual bits of a register directly, so you never hand-roll a bit mask: one register gives you bit references 0 through 15.
  • Client maps are built per client; server maps are built through the server mapping interface.
08:52C37.118 · Tag Processor · live data

When 500 milliseconds is too slow

Sample rate vs cycle time
Frame interval
16.7 ms
Cycle needed
≤ 16 ms
Verdict
OK

  • C37.118 is used for metering and delivers data faster than the alternatives. PDC ID, station name, PMU ID, port, data rate and cycle time must be configured consistently on both ends.
  • Two settings, not one. The data rate lives in the system tags; the cycle time is separate. Change only one and 60 samples per second will not work.
  • At 60 samples per second the RTAC cycle time has to be around 15–16 ms. At 100 ms the data arrives every 16 ms and the box simply never looks at most of it.
  • CMV — complex measured values — give magnitude and angle. Angles support calculations such as power factor, after converting degrees to radians.
  • An RTAC can sit in the middle as a C37.118 gateway: take one client session, alias the tags, serve several devices downstream. The real case: one meter, its only spare PMU session already in use, and two PPCs that both needed the data — an RTAC in between took the single session and served both.
  • Tag Processor maps source tags to destination tags of matching type — source on the right, destination on the left. With MV or INS data the quality and timestamp come across on their own; override the quality only if you want to compute it.
  • Live data can be made viewable or forceable in the web portal — you stop having to go online to the RTAC just to look at a value.
Outside the room · why this matters on Day 3An SEL-735 meter serves data at about 500 ms over DNP3 or SEL protocol, but around 16.67 ms over C37.118 — roughly a 5× improvement in how fast a plant controller sees the point of interconnection. Knowledge checksix questions

Six that cost time in the field

01TCP traffic is acknowledged, the link looks healthy, but the DNP3 device stays offline. First suspect?

IP is being acknowledged, so the path exists — the failure is at the application layer. A firewall would stop the traffic outright.

02You are about to update firmware on a live RTAC. What has to happen first?

The update can erase the active project and leave the RTAC looking like a new device.

03An analog value has stopped updating even though the device is online. Most likely configuration cause?

Dead band controls when instantaneous magnitude is copied to magnitude. Too wide and the value freezes — which is why instantaneous magnitude is often preferred in existing PVC projects.

04A 32-bit float lives in Modbus holding registers 0 and 1. Where does the next value start?

A 32-bit value occupies two 16-bit registers. After 0 and 1, the next value starts at 2 — the off-by-one here is a classic source of garbage readings.

05The meter reports at 60 samples per second over C37.118. What cycle time does the RTAC need?

60 samples per second is a frame every 16.7 ms. A 100 ms cycle cannot support the rate.

06You need to force a value during commissioning. Which download?

Sending only the IEC 61131-3 logic keeps the RTAC running without rebooting the whole project, but it takes forcing off the table.
